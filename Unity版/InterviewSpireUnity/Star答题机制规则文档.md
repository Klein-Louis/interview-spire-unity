# 面试尖塔 · Star 答题机制规则文档

版本：v1.0  
日期：2026-11-22  
适用范围：Unity / 团结引擎版为主，Python 版规则保持一致。

---

## 1. 设计目标

1. 让「回答问题」成为战斗的一部分，而不是外挂式答题小游戏。
2. 每张回合都给玩家一次主动表达的机会，但不强制玩家必须高分才能通关。
3. 评分规则必须**透明、可解释、离线可用**。
4. 不使用 AI 自由文本评分，不上传玩家答案，不生成虚构经历。
5. 负面惩罚可预期、可解除、不会无限叠加。

---

## 2. 核心结论

Star 不是普通卡牌，而是每回合固定存在的**额外行动卡**：

- 不进入抽牌堆、弃牌堆或消耗堆；
- 不占用 5 张手牌槽位；
- 每回合最多使用一次；
- 使用后进入「已用」状态，直到下一回合恢复；
- 打出时必须回答本回合面试官提出的问题；
- 回答被本地规则评分，评级转化为伤害与附加效果。

---

## 3. 回合流程（更新后）

```text
回合开始
  → 抽取本回合问题（同局不重复）
  → 抽 5 张手牌
  → Star 行动恢复可用
  → 玩家阶段
       ├─ 普通出牌（消耗精力）
       ├─ 使用 Star → 回答问题 → 评分 → 结算伤害/惩罚
       ├─ 跳过 Star → 敌方获得少量护甲
       └─ 结束回合
  → 敌方行动
       ├─ 结算「加压」增益（如果有）
       ├─ 清除上一轮负面状态
       └─ 施加新的负面状态
  → 下一回合
```

## 4. Star 卡定义

| 字段 | 值 |
|---|---|
| 名称 | 亮点前置（Star） |
| key | `star` |
| 类型 | `action` |
| 标签 | `star`（不参与普通题意契合判定） |
| 费用 | 0 |
| 每回合次数 | 1 |
| 是否进卡组 | 否 |
| 是否占用手牌 | 否 |
| 可否升级 | 否 |
| 可否被移除/消耗 | 否 |

UI 上 Star 固定在手牌区左侧或结束回合按钮旁，显示为独立按钮。

## 5. 问题系统

### 5.1 问题来源

每回合从岗位题库中抽取一道题：

- 岗位方向决定基础题型权重；
- 题型与现有六题型一致：技术 / 项目 / 行为 / 动机 / 压力 / 通用；
- 同一局内已问过的问题不重复；
- 题库抽完后重置记录。

### 5.2 题库字段扩展

每道题新增：

```json
{
  "id": "soft_tech_004",
  "type": "技术",
  "job": "软件开发",
  "text": "数据库索引为何多用 B+ 树？",
  "keyPoints": ["B+树", "范围查询", "哈希索引", "磁盘IO"]
}
```

`keyPoints` 为 3–5 个评分关键词，允许同义词表。

### 5.3 同义词示例

| 标准要点 | 可接受表述 |
|---|---|
| 范围查询 | 区间查询、between、范围检索 |
| 磁盘IO | 磁盘读写、IO次数、页节点 |
| 个人贡献 | 我负责、我主导、我的部分 |
| 量化结果 | 提升百分比、耗时从、增长到 |

同义词表按岗位题库维护。

## 6. 本地评分算法

### 6.1 输入

- 本题的 `keyPoints`
- 玩家输入的文本

### 6.2 预处理

1. 去除首尾空白；
2. 转小写；
3. 去除常见标点；
4. 保留中文、英文、数字。

### 6.3 评分构成（满分 100）

| 维度 | 分值 | 规则 |
|---|---:|---|
| 要点覆盖 | 60 | 命中 1 个要点 20 分，最多 3 个 60 分 |
| 结构完整 | 20 | 含「情况 / 任务 / 动作 / 结果」中至少 2 类连接词得 20，1 类得 10 |
| 具体性 | 20 | 含数字、时间、工具名、角色名中任 2 类得 20，1 类得 10 |
| 过短惩罚 | -20 | 少于 20 字直接扣 20 |
| 空答 | — | 直接判定为不合格 |

### 6.4 评级阈值

| 评级 | 分数 | 说明 |
|---|---:|---|
| 优秀 | ≥ 80 | 覆盖主要要点且有结构、有细节 |
| 合格 | 60–79 | 覆盖部分要点，表达基本成立 |
| 不合格 | < 60 | 空答、过短、要点缺失 |

评分不做浮点小数，避免玩家纠结 1 分之差。

---

## 7. 评级转伤害

| 评级 | 基础伤害 | 附加效果 |
|---|---:|---|
| 优秀 | 10 | 无 |
| 合格 | 5 | 无 |
| 不合格（评分 < 60） | 3 | 面试官获得「加压」1 层 |

说明：

- 加压只由评分低于 60 触发，与评级名称无关；
- Star 伤害不再叠加现有「题意契合 ×1.5」；
- 通用伤害牌首张 +2 也不作用于 Star；
- Star 不受精力折扣、升级加成影响；
- 敌方防御照常吸收 Star 伤害。

---

## 8. 「加压」增益

### 8.1 定义

面试官下次攻击造成的伤害 ×1.5。

### 8.2 规则

- 最多 1 层，不可叠加；
- 只在面试官攻击**实际造成自信伤害**后消耗；
- 若攻击被镇定完全抵消，加压保留到下一次造成伤害的攻击；
- 若面试官本回合使用防御或回血，加压也保留；
- 造成伤害后清除；
- 读档后仍保留；
- UI 必须提前显示，例如意图栏显示「加压：下次攻击 ×1.5」。

### 8.3 设计理由

惩罚明确但可规划。玩家低分后会知道下一回合要留镇定或防御牌。

---

## 9. 跳过 Star

玩家可以选择「跳过本题」。

| 项目 | 规则 |
|---|---|
| 伤害 | 0 |
| 评分 | 不评分 |
| 加压 | 不触发 |
| 惩罚 | 面试官获得 10 点防御，最多累计 20 点 |
| 目的 | 让跳过有代价，但不逼迫玩家答题 |

这样不擅长表达的玩家仍可通过卡组通关，只是难度更高。

---

## 10. 与现有系统的交互

| 系统 | 交互规则 |
|---|---|
| 题意契合 ×1.5 | 仅普通牌生效，Star 不叠加 |
| 消耗堆 | Star 不进入 |
| 抽牌/洗牌 | Star 不参与 |
| 负面状态 | 不受自我怀疑影响，伤害固定按评级 |
| 镇定 | 只抵挡敌方攻击，不影响 Star 伤害 |
| 追问链 | 技术牌触发，Star 不触发 |
| 通用首张 +2 | 不作用于 Star |
| 存档 | 保存 `starUsedThisTurn`、已问题目 ID、加压状态 |
| 读档 | 恢复上述问题，不保存玩家答案文本 |

## 11. UI 流程

### 11.1 玩家阶段

手牌区固定显示：

```text
[ Star · 亮点前置 ] [ 手牌 1 ] ... [ 手牌 5 ] [ 结束回合 ]
```

Star 按钮状态：

- 可用：金色描边；
- 已用：灰色，不可点击；
- 题目弹窗打开时：底层面牌不可点击。

### 11.2 答题弹窗

```text
┌─ 本回合问题 · 技术 ────────────────┐
│ 数据库索引为何多用 B+ 树？          │
│ 考察点：存储结构 / 范围查询         │
│                                  │
│ [ 多行输入框 ]                     │
│                                  │
│ [ 提交回答 ]  [ 跳过本题 ]          │
└──────────────────────────────────┘
```

### 11.3 评分反馈弹窗

```text
评级：优秀（86）
伤害：18 + 2 = 20

命中要点：B+树、范围查询、磁盘IO
缺失要点：哈希索引对比
建议：补一句与哈希索引的对比会更完整。
```

反馈必须包含：

1. 评级；
2. 分数；
3. 伤害；
4. 命中要点；
5. 一条具体改进建议。

## 13. 平衡目标

以标准难度 4 轮为基准：

| 行为 | 期望效果 |
|---|---|
| 每次优秀回答 | 10 伤害 |
| 每次合格回答 | 5 伤害 |
| 每次低于 60 分 | 3 伤害 + 下次受击 ×1.5 |
| 全程跳过 Star | 可通关，但需更多防御与运营 |
| 全程优秀 | 明显轻松，但不无脑 |

建议调整敌方血量前先跑 100 次自动对局，记录：

- 平均通关率；
- 平均回合数；
- 低分次数；
- 加压触发次数；
- 跳过次数。

---

## 14. 验收测试

必须覆盖以下 10 项：

1. 每回合 Star 可用一次，用后禁用。
2. Star 不进入抽牌/弃牌/消耗堆。
3. 同局问题不重复。
4. 空答判定不合格。
5. 命中 3 个要点且结构完整判定优秀。
6. 不合格施加 1 层加压。
7. 加压不可叠加。
8. 加压在下次攻击时消耗并清除。
9. 跳过 Star 给 10 点防御，最多 20 点。
10. 存档读档后 Star 状态、已问题目、加压状态保持一致。

## 15. 分阶段实现

### 阶段一：最小可玩

- Star 按钮与答题弹窗；
- 关键词评分；
- 三档伤害；
- 加压状态；
- 跳过按钮。

### 阶段二：题库增强

- 90 道题补 `keyPoints`；
- 同义词表；
- 反馈建议模板。

### 阶段三：平衡与测试

- 自动对局统计；
- 敌方血量微调；
- 单元测试覆盖 10 项验收。

---

## 16. 明确不做

- 不上传玩家答案；
- 不调用 AI 评分；
- 不生成虚构个人经历；
- 不保存玩家自由文本答案；
- 不做无限叠加惩罚；
- 不让 Star 参与普通卡牌的伤害加成体系。

---

## 17. 一句话规则

> 每回合用 Star 回答一道不重复的问题，答案按透明规则评分并转成伤害；答差会让面试官下次攻击更痛，跳过则让它更耐打。

## 阶段三平衡结果

- 敌方血量：44/60/76/96 → 40/54/68/86。
- 敌方攻击与防御整体下调约 8%–15%。
- 卡牌微调：降低高爆发牌（STAR 法则 14→12、性能调优 18→16、展示作品集 20→17 等），提高基础牌稳定性（有条理的回答 7→8、深呼吸 5→9 等），防御与恢复牌同步小幅收敛。
- 100 局 × 3 策略的模拟结果：优秀回答通关率 23%，合格回答 13%，跳过 Star 1%；平均回合约 8。
